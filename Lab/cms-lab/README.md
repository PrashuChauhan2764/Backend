# Simple CMS – Backend Development Lab

A simple **Blog Content Management System (CMS)** built using **Node.js, Express.js, EJS and MongoDB**.

The application allows users to create blog posts, view all posts, and open an individual post to read its complete content.

---

## Tech Stack

- **Node.js** – Runs the backend
- **Express.js** – Handles the server and routes
- **EJS** – Server-side HTML templates
- **MongoDB** – Stores blog posts
- **MongoDB Node.js Driver** – Connects Node.js with MongoDB
- **HTML/CSS** – User interface

### Why Option A?

I chose **Node.js + Express + EJS + MongoDB** because I already had experience with Node.js and Express, and this stack allows the complete CMS to be built with simple and understandable code.

I used the **MongoDB native driver instead of Mongoose** because Mongoose was not required for the exam and the native driver keeps the project simpler.

---

## Features

- Create a new blog post
- Validate title, content and author
- Automatically generate creation date on the backend
- Store posts permanently in MongoDB
- Display all posts, newest first
- Click a post title to open the complete post
- Retrieve individual posts using MongoDB `_id`
- Server-side rendering using EJS
- Simple CSS-based interface

## MongoDB

The project uses the local MongoDB server.

```text
URL        : mongodb://127.0.0.1:27017
Database   : cms_lab
Collection : posts
```

A post is stored like:

```json
{
  "title": "Introduction to MongoDB",
  "content": "MongoDB is a document-oriented database.",
  "author": "Prashu",
  "createdAt": "Generated automatically",
  "_id": "Generated automatically by MongoDB"
}
```

The user does not enter `createdAt`. The backend generates it using:

```javascript
createdAt: new Date()
```

## Application Flow

### Create Post

```text
/posts/new
     ↓
User fills the form
     ↓
POST /posts
     ↓
Validate input
     ↓
Generate createdAt
     ↓
Insert into MongoDB
     ↓
Redirect to /
```

### Display Posts

```text
GET /
   ↓
Retrieve posts from MongoDB
   ↓
Sort by createdAt
   ↓
Send data to posts.ejs
   ↓
Display post list
```

### Open Individual Post

```text
Click post title
      ↓
GET /posts/:id
      ↓
Get MongoDB _id from URL
      ↓
Find post using ObjectId
      ↓
Send post to post.ejs
      ↓
Display complete content
```

---

## Routes

| Method | Route | Purpose |
|---|---|---|
| GET | `/` | Display all posts |
| GET | `/posts/new` | Display create-post form |
| POST | `/posts` | Validate and create post |
| GET | `/posts/:id` | Display one complete post |

## Challenges & Debugging

While building the project, I learned the application step-by-step instead of creating everything at once.

Important concepts I had to understand:

- How Node.js connects to MongoDB.
- Difference between `GET /posts/new` and `POST /posts`.
- How HTML form data reaches Express through `req.body`.
- Why `createdAt` is generated by the backend instead of the form.
- How MongoDB `_id` is passed through `/posts/:id`.
- Why `ObjectId` is required when finding a MongoDB document by `_id`.
- How EJS receives backend data and generates HTML.
- How MongoDB persistence keeps posts after restarting the server.

I tested each part separately:

```text
MongoDB connection
      ↓
Create form
      ↓
Data insertion
      ↓
Post list
      ↓
Individual post
      ↓
Validation
      ↓
Persistence after restart
```
